# CLAUDE.md

Working notes for agents in this repository. See `README.md` for how the site
itself is built.

## Golden rule — never publish private Claude links

**Nothing that leaves this repository may contain a Claude session link, an
artifact link, or any other private or account-scoped URL.** This repository is
public; those links are not. Treat this as non-negotiable.

It applies to every surface, with no exceptions:

- commit messages, including trailers
- pull request titles and descriptions
- pull request comments, issue comments and review replies
- source files, code comments, documentation and assets
- release notes, tags, and anything else pushed or published from here

Specifically, none of these belong anywhere in this repo or on anything posted
from it:

```
https://claude.ai/code/session_...        ← session link
https://claude.ai/code/artifact/...       ← artifact link
Claude-Session: ...                       ← commit trailer
```

`Co-Authored-By: Claude ...` is fine. It is attribution and carries no private
link.

Share previews and session context with the author directly, in the
conversation — never by committing or posting a link to them.

### Read it back after posting

The rule is not satisfied by writing a clean body. **Some tooling appends its
own footer server-side, after your text.** PR #1 in this repository was opened
with a description that contained no links, and came back with this appended:

```
_Generated by [Claude Code](https://claude.ai/code/session_...)_
```

So, after creating or editing a pull request, issue or comment: fetch it again,
read the stored body, and confirm nothing was added. If a private link appears,
edit it out and verify a second time.

The same applies to history. Before pushing, check that no commit message on
the branch carries a session trailer:

```bash
git log <base>..HEAD --format=%B | grep -nE "claude\.ai|session_|Claude-Session"
```

If one slipped through, rewrite the messages and force-push with
`--force-with-lease` — the trees must come out byte-identical, so verify with
`git diff` against the original branch before replacing it.
